Closest true peers: cjdns, tinc, Yggdrasil — and wgmesh's own LAN path

Every SaaS/open-core tool in the table still needs something centralized. Three no-server projects genuinely share wglan's "actually offline" claim, plus one path inside wglan's own ancestor:

  • cjdns — UDP beacon auto-peers on LAN, no server ever, but addressing is derived from a cryptographic scheme rather than operator-chosen; no static inventory, no /etc/hosts naming, no shipped firewall skeleton.
  • tinc — a one-time manual host-file exchange, then zero network calls forever. Closest in spirit to "join once, nothing on a timer" — but the exchange is N-way manual file copying, not one shared secret plus one bootstrap IP.
  • Yggdrasil — self-organizing, no bootstrap secret at all. Strong on LAN auto-discovery, but pubkey-derived addressing (no operator-chosen subnet) and nothing like wglan's symmetric leave or host firewall skeleton.
  • wgmesh's own LAN-multicast layer — the same "actually offline" claim, but it's one path inside a much larger daemon that also resolves public DHT bootstrap hostnames on every start by default. wglan has none of that surface to audit or disable in the first place.

None of the four combine wglan's specific bet: a shared secret is the entire membership mechanism, addressing is static from an inventory instead of derived, and nothing runs on a timer once a join completes. That combination — not "works offline" alone — is the axis wglan is actually optimizing.

02 · Feature inventory

What wglan ships, and what it doesn't yet

One binary, one operating mode — so this is one inventory, not per-mode tables. Status: ✅ shipped · 📋 deferred, with the trigger that would justify building it.

Envelope & protocol

FeatureNotes
✅ wglan secretGenerates the shared secret the envelope key derives from.
✅ AES-256-GCM sealed envelopeOne primitive for confidentiality and the membership proof — opening it is the proof (SPEC §4).
✅ HKDF key derivationFrom the shared secret; stdlib crypto/hkdf as of Go 1.24.
✅ Freshness window±10 minutes, both directions — rejecting only "too old" would leave a future-dated capture replayable once its time arrived.
✅ Nonce seen-setReplay defense, bounded by the freshness window.
✅ Validation welded to OpenNo code path yields an unvalidated payload struct (SPEC §4.5).
✅ Uniform pre-auth rejectionWrong key, wrong version, stale timestamp, and malformed bytes are indistinguishable on the wire by construction.

Join, leave, repair, probe

FeatureNotes
✅ wglan joinFull mesh from one bootstrap IP — the joiner unions the peer list it's handed and greets every member directly, then returns. Setup is a command that finishes, not a process.
✅ wglan runThe long-lived control listener, and the only thing a service manager supervises. Splitting it from join is what lets every other verb be re-run against a node whose daemon already holds the port.
✅ Duplicate-address / colliding-pubkey rejectionNo exemption for an already-known pubkey (SPEC §3.4) — the draft-1 bug that let a member move a victim's address onto its own key.
✅ peers.json atomic load/saveRestart reloads directly, no network round trip, no re-bootstrap.
✅ Managed /etc/hosts block<node>.mesh entries; everything outside the markers survives byte-for-byte, even against a hostile file.
✅ wglan leaveSeals a LEAVE, fans out to every peer, then deletes the wglan0 interface after announcing.
✅ LEAVE bound to tunnel + sender's own mesh IPOtherwise any member could evict any other — WireGuard's cryptokey routing proves the sender before wglan code runs (SPEC §6.1).
✅ wglan forget <pubkey>Operator cleanup for a node that's already gone.
✅ wglan syncRepairs a missing edge after two joins race — the JOIN path, outside the tunnel, envelope as its only authentication. Fans out exactly as a join does, so one invocation on either node closes the edge in both directions; without that it would teach us about a peer and leave the peer ignorant of us, which in WireGuard means no handshake either way.
✅ wglan probeLiveness corroboration across peers; in-tunnel and source-bound like LEAVE, not a repurposed sync.

Hardening & status

FeatureNotes
✅ Pre-auth hardeningRate limiter, 8-connection semaphore, I/O deadlines — all applied before a decrypt is attempted (SPEC §12.2).
✅ wglan statusStale marker at 180s handshake age (WireGuard's own threshold); transfer counters printed alongside for a human to disagree with.
✅ Argv-array exec.Command onlyNever a shell string built from a peer-controlled field — the injection guarantee tests assert on argv, not a rendered string.

Host firewall

FeatureNotes
✅ wglan firewallPrints the embedded nftables skeleton with --interface/--control-port filled in — never edits nftables itself (SPEC §12.5).
❌ --no-firewallExisted briefly while the daemon still edited nftables at startup; removed once the firewall became file-only — there's nothing left for it to opt out of (SPEC §17).

03 · What this tells us

Narrow on purpose, not narrow by accident

Three things stand out reading both halves together.

The first is that wglan trades breadth for auditability on purpose. Every ❌ in the competitive matrix traces to a non-goal recorded in SPEC §2 or a deferral in IMPLEMENTATION.md with its own trigger condition — nothing in that column is an accidental gap, and none of it is hidden here.

The second is that wglan's real competitive set isn't the SaaS mesh tools at all — it's the handful of no-server tools (cjdns, tinc, Yggdrasil) and the one LAN-multicast path buried inside a much larger wgmesh. Against that set, the differentiator is narrow but real: a shared secret is the entire membership mechanism, addressing is static and operator-chosen rather than derived, and nothing ever runs on a timer.

The third is that the shipped list is almost the whole list. The deferred table is short because most of what a bigger mesh tool eventually needs — ACLs, revocation, structured logging — was scoped out at the spec stage rather than left half-built. Everything not listed as deferred is implemented, tested under -race, and has an acceptance check that was actually run (IMPLEMENTATION.md's six milestones).

Where wglan wins
  • Genuinely zero background logic — no reconcile loop, no beacon, no timers, ever, once a join completes.
  • Full mesh from one bootstrap IP, exact convergence proven by induction — not gossip, not eventual consistency.
  • Sealing the message is the proof of membership — no separate token, no unused membership primitive to maintain.
  • Small enough to read in one sitting — one main package, six files, one isolated package, zero third-party dependencies.
  • The firewall is a file you own, never a table applied at runtime — survives an nftables restart.
Where wglan loses
  • LAN + one bootstrap IP only — no NAT traversal, no path to an internet-wide mesh at all.
  • No ACLs — membership is total; nothing scopes who can talk to whom once joined.
  • No revocation — removing a node is a secret rotation, a flag day, not a command.
  • No encrypted state at rest — peers.json sits on disk in plaintext.
  • No mobile, GUI, or DNS server — CLI and /etc/hosts, nothing else.
  • No packaging at all — go build ./... is the entire release process; solo maintainer, no ecosystem.
→ positioning

wglan is for the LAN that has no business talking to the internet at all — a lab, a fleet of self-hosted boxes, an air-gapped network. If the mesh needs to span the internet, needs ACLs, or needs to be reachable from a phone, wglan is the wrong tool by design, not by oversight — wgmesh, Tailscale, or Netbird answer that. If the requirement is "a handful of boxes on one LAN, one secret, and nothing that ever wakes up on its own," this is the tool built for exactly that and nothing more.
